# DTU supplied matched directions for all 49 screened camera positions

Every position in the common 49-camera robot trajectory matched a predominantly horizontal and a predominantly vertical candidate under the registered pose criteria. This uses only camera projection matrices. Visibility against the independent structured-light geometry and image-based depth accuracy are subsequent checks. The same camera path repeats across laboratory scenes. [Registered pose screen](PLAN.md) · [Matrix hashes and selected view IDs](results/geometry.json) · [Official DTU dataset and citation terms](https://roboimagedata.compute.dtu.dk/?page_id=36)

The camera files were fetched by byte range from the official SampleSet archive. This kept the download limited to calibration entries. The pilot draws 12 evenly spaced reference identities from the qualified path before viewing image or depth outcomes. It stages neutral-light exposure 3 from the archive's scans 1 and 6, the two structured-light point clouds, and the required projection matrices. The stage preserves a checksum manifest and keeps the source images and scans outside Git. [Selective staging script](stage.py) · [Jensen et al., CVPR 2014](https://openaccess.thecvf.com/content_cvpr_2014/html/Jensen_Large_Scale_Multi-view_2014_CVPR_paper.html)

Both staged scenes passed the common-visibility gate on all 12 reference triplets. The shared sample ranged from 34,973 to 68,616 reference pixels per triplet. The projected depth buffer uses quarter-resolution pixels and a 5 mm front-surface tolerance. The next comparison uses these reference points to score the repetition cue and a structure-tensor baseline with identical camera budgets.
